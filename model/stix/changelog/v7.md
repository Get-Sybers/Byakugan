# car-stix-projection contract v7 — change log

**Status: landed.** `conventions.yml` `contract.version` 6 → 7; the schema set
(`model/schema/constants.yaml` `schema_version`, rendered into the evidence
`extension-definition.version`) 6.0.0 → 7.0.0. **No id moves:** every
deterministic id — producer, extension-definitions, SCOs, observations, the
catalogue — keeps its recipe and its value.

## The delta

The repository moved from GitLab to GitHub, and the URL-valued properties on
the wire still carried GitLab path forms (`…/-/issues`, `…/-/blob/…`,
`…/-/raw/…`) that 404 on GitHub. v7 is the URL correction and nothing else:

| object | property | v6 | v7 |
|---|---|---|---|
| producer identity (`DEFAULT_CONTACT`) | `contact_information` | `github.com/Get-Sybers/Byakugan/-/issues` | `github.com/Get-Sybers/Byakugan/issues` |
| extension-definition `dxdfir` | `external_references[0].url` | `…/-/blob/main/docs/STIX-Exchange.md` | `…/blob/main/docs/STIX-Exchange.md` |
| extension-definition `dxdfir-evidence` | `schema` | `github.com/…/-/raw/main/model/schema/extensions/dxdfir-evidence.schema.json` | `raw.githubusercontent.com/Get-Sybers/Byakugan/main/model/schema/extensions/dxdfir-evidence.schema.json` — the schema file's own `$id` |
| extension-definition `dxdfir-evidence` | `external_references[0].url`, `version` | `…/-/blob/main/model/stix/changelog/v6.md`, `6.0.0` | `…/blob/main/model/stix/changelog/v7.md`, `7.0.0` |
| indicator (rules-as-code export, `RULE_URL`) | `external_references[].url` | `…/-/blob/main/rules/<id>.yml` | `…/blob/main/rules/<id>.yml` |

STIX 2.1 §3.6: a changed property is a new version of the object, so the
producer identity's `modified`, both extension-definitions' `modified` and
the evidence extension's `version` move with it (`byakugan/exchange/objects.py`:
`IDENTITY_MODIFIED`, `EXTENSION_MODIFIED`, `EVIDENCE_EXTENSION_MODIFIED`,
`EVIDENCE_EXTENSION_VERSION`); `created` never moves. The `dxdfir` extension's
`version` (1.1.0) stays: its schema is unchanged. The car projection's own
producer identity (`byakugan/stix.py` `PRODUCER`) already carried a GitHub
URL and does not move.

## Migration

A consumer re-importing a v7 bundle sees the same ids with later `modified`
stamps — an ordinary object update under STIX versioning. Nothing to re-key,
nothing to re-pull.
